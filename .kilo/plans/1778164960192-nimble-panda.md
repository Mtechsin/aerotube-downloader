# Error Handling & Logging Plan for AeroTube

## Current State Summary
- **LoggingService** exists with dev logs (max 1000) and user logs (max 5), but:
  - No logging toggle — always on
  - No old log file cleanup — single app.log grows forever
  - 29 print() statements across 10 files that bypass the logging system
  - No global error boundary (runZonedGuarded / FlutterError.onError)
- **ErrorHelper** exists but only handles 4 error patterns; default truncates to 100 chars
- No structured way to show errors to users consistently

---

## Implementation Plan

### Phase 1: Global Error Boundary (main.dart)
**Objective:** Wrap the app in runZonedGuarded + FlutterError.onError so no error silently crashes the app.

**Changes in `lib/main.dart`:**
1. Import `dart:async` at the top
2. After `WidgetsFlutterBinding.ensureInitialized()`, set `FlutterError.onError` to log to LoggingService
3. Wrap `runApp()` in `runZonedGuarded` to catch async errors
4. Both handlers log the error AND show a user-facing log via `showUserLog()`

**Code to add:**
```dart
void main() async {
  WidgetsFlutterBinding.ensureInitialized();

  // Global error handling
  final loggingService = LoggingService();
  await loggingService.init();

  FlutterError.onError = (details) {
    loggingService.error(
      'Flutter error: ${details.exception}',
      error: details.exception,
      stackTrace: details.stack,
    );
    loggingService.showUserLog(
      'An unexpected error occurred',
      isError: true,
    );
  };

  runZonedGuarded<Future<void>>(() async {
    // ... rest of initialization and runApp
  }, (error, stackTrace) {
    loggingService.error(
      'Uncaught async error: $error',
      error: error,
      stackTrace: stackTrace,
    );
    loggingService.showUserLog(
      'An unexpected error occurred',
      isError: true,
    );
  });
}
```

**Note:** The `loggingService` needs to be initialized early and made available. We'll need to restructure slightly to ensure the service is available for error handling before other services initialize.

### Phase 3: Implement Log File Rotation/Cleanup
**Objective:** Prevent single app.log from growing forever.

**Changes in `lib/services/logging_service.dart`:**
1. Add constants:
   - `static const int _maxLogFileSize = 5 * 1024 * 1024; // 5MB`
   - `static const int _maxLogFiles = 3; // Keep 3 rotated files`

2. Add method `_rotateLogFileIfNeeded()`:
   - Check current file size before writing
   - If > max size, rotate: app.log → app.log.1, app.log.1 → app.log.2, etc.
   - Delete oldest if exceeds max files

3. Modify `_writeToFile()` to call rotation check periodically (e.g., every 100 writes or check file size)

4. Add method `cleanupOldLogs()`:
   - Delete log files older than X days (e.g., 30 days)
   - Call during initialization
