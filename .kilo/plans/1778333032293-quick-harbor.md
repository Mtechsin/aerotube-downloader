# Plan: Add ABI Split for Android Release Builds

## Problem
The Android APK is 100+MB because `youtubedl-android` bundles native binaries (FFmpeg, yt-dlp, aria2c) as `*.zip.so` files. On every update, users download the full APK including architectures they don't need.

## Solution
Enable ABI splitting in the Android Gradle build so each architecture gets its own APK. When uploaded to Google Play as an App Bundle (`.aab`), Play Store delivers only the appropriate APK per device. Universal APKs can also be generated for sideloading.

## Changes

### 1. `android\app\build.gradle.kts` — Add ABI split configuration

**Current state (lines 31-52):**
```kotlin
buildTypes {
    release {
        isMinifyEnabled = true
        isShrinkResources = true
        proguardFiles(...)
        signingConfig = signingConfigs.getByName("debug")
    }
}

packaging {
    jniLibs {
        keepDebugSymbols += setOf("**/*.zip.so")
    }
}
```

**New state:**
```kotlin
android {
    // ... existing config ...

    defaultConfig {
        // ... existing config ...
        // Restrict to only the ABIs we support, reducing APK size
        ndk {
            abiFilters += listOf("arm64-v8a", "armeabi-v7a", "x86_64")
        }
    }

    buildTypes {
        release {
            isMinifyEnabled = true
            isShrinkResources = true
            proguardFiles(...)
            signingConfig = signingConfigs.getByName("debug")
        }
    }

    // Generate separate APKs per ABI architecture
    splits {
        abi {
            isEnable = true
            reset()
            include("arm64-v8a", "armeabi-v7a", "x86_64")
            isUniversalApk = true  // Also generate a universal APK containing all ABIs
        }
    }

    packaging {
        jniLibs {
            keepDebugSymbols += setOf("**/*.zip.so")
        }
        resources {
            // Exclude unneeded resource configs to reduce size further
            excludes += setOf(
                "META-INF/*.kotlin_module",
                "META-INF/*.version",
                "META-INF/native/**"
            )
        }
    }
}
```

### 2. `android\gradle.properties` — No changes needed
The existing properties don't conflict with ABI splitting.

### 3. `AndroidManifest.xml` — No changes needed
`extractNativeLibs="true"` is already set, which is required for split APKs to work correctly.

### 4. Build commands for separate APKs

**Generate App Bundle (recommended for Play Store):**
```bash
flutter build appbundle --release
```
This produces a `.aab` file. Google Play delivers the correct ABI split automatically.

**Generate split APKs (for sideloading):**
```bash
flutter build apk --release --split-per-abi
```
This produces separate APKs:
- `app-arm64-v8a-release.apk`  (typically ~30-40MB)
- `app-armeabi-v7a-release.apk` (typically ~25-35MB)
- `app-x86_64-release.apk`     (typically ~25-35MB)
- `app-universal-release.apk`  (all ABIs, for sideloading ~90-100MB)

### 5. Version compatibility note
The `splits.abi` DSL with `isEnable`, `reset()`, `include()`, and `isUniversalApk` is the older but still fully supported Gradle plugin syntax (compatible with AGP 8.x used here — `com.android.application` version `8.9.1`). The newer preferred way uses `android.experimental.buildDefaultTargeting` in `gradle.properties`, but the DSL approach is more explicit and reliable.

## Expected Results
- arm64-v8a APK: ~30-40MB (most modern devices)
- armeabi-v7a APK: ~25-35MB (older 32-bit ARM devices)
- x86_64 APK: ~25-35MB (emulators, some tablets)
- Universal APK: ~90-100MB (contains all ABIs for sideloading)

## Debugging Impact
- **No impact.** Debug builds are unaffected — `splits` only applies to release builds by default.
- The `debug` build type doesn't use ABI splitting unless explicitly configured.
- `flutter run` and `flutter run --debug` continue to work normally.

## Risks
- Low risk: This is standard Android Gradle configuration used widely.
- The `keepDebugSymbols += setOf("**/*.zip.so")` rule is preserved so youtubedl-android's `.zip.so` archives aren't stripped.
- Proguard rules already include Play Core splitcompat warnings (`proguard-rules.pro` lines 42-53), confirming split APK support was already anticipated in the codebase.
