# Android Download Completion Fix Plan

## Problem Summary
Android downloads reach 100% in logs but don't complete/finalize properly. The download shows progress but the file isn't properly saved/accessible.

## Root Causes Identified

1. **Output Path Bug** (MainActivity.kt:296)
   - Dart passes full file path: `/storage/.../Videos/What did the airport paint overnight_.mp4`
   - Native appends: `%(title)s.%(ext)s`
   - Results in: `/storage/.../Videos/What did the airport paint overnight_.mp4/%(title)s.%(ext)s` (invalid)
   - yt-dlp treats the filename as a directory

2. **Fake Progress Tracking** (mobile_download_provider.dart:284-320)
   - `_trackDownloadById` simulates progress with `lastProgress += 0.05` loop
   - Never actually waits for download to complete
   - Calls `_completeDownload` after simulated 100%, but file may still be downloading

3. **Missing Completion Callback**
   - `YoutubeDL.execute()` in native code runs asynchronously
   - The method returns immediately after starting download
   - No way for Dart to know when download actually finishes
   - Progress callback only shows percentage, not completion event

4. **Storage Permission Edge Cases**
   - App-specific directory should work without permissions on Android 10+
   - But need to verify directory creation/write access works

## Solution Strategy

### Phase 1: Fix Output Path Construction

**File**: `MainActivity.kt`

Change the downloadVideo function to:
- Accept two separate paths: `outputDir` (directory) and optionally `outputTemplate` (filename template)
- OR modify to NOT append template if path already includes filename
- Recommended approach: Send directory path from Dart, let native construct full template

**In `native_ytdlp_android.dart` and `ytdlp_service_android.dart`:**
- Pass `outputPath` as directory only
- Use template: `"$outputPath/%(title)s.%(ext)s"`

### Phase 2: Implement Real Completion Detection

**Option A (Preferred)**: Use youtubedl-android's built-in completion

The library's `execute(request, processId, progressCallback)` may block until completion or provide completion callback. Need to check library documentation.

**Implementation**:
1. In `MainActivity.kt`, make the download call synchronous or add completion listener
2. Return only after download fully completes
3. OR implement a callback method to notify Dart when download finishes

**Option B**: Poll process status

1. Add a new method `isDownloadComplete(processId)` in native side
2. Poll this from Dart until true
3. More complex but more reliable for async operations

**Recommended**: Modify native `downloadVideo` to wait for completion before returning success, since yt-dlp runs synchronously in that thread anyway.

### Phase 3: Propagate Real Progress

Replace simulated progress with actual progress from native callback:

1. In `MainActivity.kt`, send progress updates to Dart via MethodChannel (event/stream)
2. In Dart, receive real progress and update UI
3. When progress reaches 100% and download completes, mark as completed

### Phase 4: Enhance Permissions & Storage

1. Verify `AndroidStorageService.requestStoragePermission()` handles all Android versions correctly
2. Add fallback to app-specific directory if external storage fails
3. Ensure directory existence before download starts
4. Add file accessibility verification after download

### Phase 5: Robust Error Handling

1. Capture native exceptions and propagate to Dart
2. Detect common failures: insufficient storage, network errors, format issues
3. Provide user-friendly error messages
4. Auto-retry mechanism for transient failures

### Phase 6: Windows Compatibility

- Ensure all changes are Android-specific
- Use `#if android` or platform checks in Dart
- Do not modify Windows desktop code paths
