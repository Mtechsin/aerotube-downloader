# Plan to Fix Windows Resolution Solver

## Problem Analysis

The Windows side of the Flutter app only fetches **combined video+audio formats** (typically 360p) instead of separate video-only and audio-only streams across all resolutions (144p to 4K). The Android implementation works correctly.

**Root cause**: In `lib/services/ytdlp_service.dart`, the `YtdlpService` uses a hardcoded `--extractor-args` value:
```dart
'youtube:player_client=web,android,mweb,ios;formats=all'
```

This forces yt-dlp to use the `android` client, which is now **deprecated and broken** (removed from defaults in yt-dlp 2024+). The broken `android` client often returns only a single combined format (e.g., format 18 = 360p), limiting the entire format set.

Additional issues:
- `formats=all` is not a valid yt-dlp format option (valid values are `dashy`, `duplicate`, `incomplete`). It is likely ignored.
- The retry logic also uses the same outdated client list and incorrect `player-skip` (should be `player_skip` with underscore).

## Solution

Update the extractor arguments to use yt-dlp's **default client list**, which as of 2026 is:
- Normal (JS-enabled): `android_sdkless,web,web_safari`
- Automatically adjusts for authentication.

Using `player_client=default` lets yt-dlp pick the optimal clients based on environment and authentication state.

## Implementation Steps

1. **Open** `lib/services/ytdlp_service.dart`.

2. **Locate** the three occurrences of `--extractor-args` that specify `player_client`:
   - In `_buildCommonArgs()` (around line 682-683):
     ```dart
     '--extractor-args',
     'youtube:player_client=web,android,mweb,ios;formats=all',
     ```
   - In `getVideoInfo()` (around line 317-318):
     ```dart
     '--extractor-args',
     'youtube:player_client=web,android,mweb,ios;formats=all',
     ```
   - In the retry block within `getVideoInfo()` (around line 366-367):
     ```dart
     '--extractor-args',
     'youtube:player_client=web,mweb,android,ios;player-skip=webpage,configs;formats=all',
     ```

3. **Replace** the extractor args:
   - In the first two locations, change the value to:
     ```dart
     'youtube:player_client=default'
     ```
   - In the retry location, change to:
     ```dart
     'youtube:player_client=default;player_skip=webpage,configs'
     ```
     (Note: corrected `player_skip` to use underscore, which is the proper yt-dlp extractor argument.)

4. **Save** the file.

## Expected Outcome

After the change, yt-dlp should return a full set of formats including separate video-only and audio-only streams spanning resolutions from 144p to 4K+. Debug logs should show:
```
[VideoInfo] Total formats received: XX  (>10)
[VideoInfo] Video-only: X, Audio-only: X, Combined: X
[VideoInfo] Available resolutions: 144, 240, 360, 480, 720, 1080, 1440, 2160
```

## Notes

- No other code needs modification; the fix is confined to the service's command-line arguments.
- The change is safe for all desktop platforms (Windows, Linux, macOS) as it aligns with current yt-dlp best practices.
- The Android service uses a native library and remains untouched as requested.
