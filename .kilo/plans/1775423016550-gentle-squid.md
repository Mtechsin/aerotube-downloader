# Plan: Redesign Android Fetch Screen

## Current State Analysis

### Desktop Implementation (VideoConfigurationWidget)
- Split-view layout (thumbnail left, controls right)
- Resolution chips selector (horizontal scroll)
- Variant/codec list with detailed format info
- Audio merge selection dropdown (when video has no audio)
- Audio-only mode with quality tier chips and audio stream list
- Subtitle smart selection (top 3 chips + expansion for more)
- Large download button with progress indicator

### Mobile Implementation (MobileFetchScreen)
- Currently shows basic video info card with only Clear/Download buttons
- No detailed format/audio/subtitle selection UI
- VideoProvider already supports all selection logic (resolutions, audio, subtitles)

## Design Goals for Android

1. **Resolution Selectors**: Semi-rounded top design below title, title should not wrap
2. **Codec Selection**: Show different codecs for each resolution with good UI/UX
3. **Audio Selection**: Separate section for audio (merged later with FFmpeg)
4. **Subtitle Selection**: Non-cramped, clever UX
5. **Mobile-First**: Optimized for vertical scrolling on small screens
6. **Keep Desktop Untouched**: Only modify mobile files

## Proposed Mobile Layout

### Structure
```
Video Result Card (Container with rounded corners)
├── Video Info Section
│   ├── Thumbnail (16:9 aspect ratio, left side)
│   └── Metadata (right side: title (single line), channel, duration)
│
├── Resolution Section
│   ├── Section Title: "RESOLUTION"
│   ├── Resolution Chips (horizontal scroll, pill-shaped, semi-rounded top)
│   └── Variants List (cards showing codec, fps, size, HDR badge)
│
├── Audio Section (conditional: when video-only stream selected)
│   ├── Section Title: "AUDIO TRACK"
│   └── Audio streams dropdown/list
│
├── Subtitles Section (if subtitles available)
│   ├── Header with "Embed" toggle
│   ├── Top 3 subtitle chips
│   └── Expansion for more (similar to desktop)
│
└── Download Section (footer)
    ├── Clear button
    └── Download button with size estimate
```

### Key Design Elements

1. **Resolution Chips**: Pill-shaped (`RoundedRectangleBorder` with radius 20), horizontal scroll, primary color when selected
2. **Variant Cards**: Compact cards showing:
   - Codec icon + name (e.g., "AV1", "H.264", "VP9")
   - Container format (MP4, WebM)
   - HDR/60fps badges
   - Size estimate
   - Radio button indicator
3. **Audio Selection**: Dropdown button or compact list for audio track merging
4. **Subtitles**: Chips with checkmarks, embed toggle, expandable overflow
5. **Spacing**: Generous padding (16-20px) to avoid cramming
6. **Typography**: Clear section headers (12-13px, uppercase, muted color)

## Implementation Plan

### Step 1: Create Mobile Video Configuration Widget
- Create new file: `lib/ui/widgets/mobile_video_configuration_widget.dart`
- Extract video info display logic from current `_buildVideoResult` in `mobile_fetch_screen.dart`
- Create compact layout: thumbnail + metadata side-by-side (or stacked on very small screens)

### Step 2: Implement Resolution Selection
- Add resolution chips row (horizontal scroll)
- Use `provider.availableResolutions` to generate chips
- On selection, call `provider.selectResolution(option)`
- Display variants list below with codec details
- Each variant card shows: codec name, extension, size, HDR/60fps badges, radio selection

### Step 3: Implement Audio Track Selection
- Show only when selected video format has no audio (`provider.selectedVideoFormat?.hasAudio == false`)
- Use `DropdownButton` or list to select from `provider.videoInfo!.audioOnlyFormats`
- Call `provider.setSelectedAudioMergeStream(format)` on change
- Label: "Audio Track to Merge"

### Step 4: Implement Subtitle Selection
- Show only if `provider.videoInfo!.subtitles.isNotEmpty`
- Header with "Embed Subtitle" toggle
- Top 3 subtitles as selectable chips
- Expansion tile for remaining subtitles
- Call `provider.toggleSubtitle(sub)` on chip tap
- Show checkmark on selected chips

### Step 5: Download Button Section
- Footer with two buttons:
  - Clear (outlined): resets everything
  - Download (filled): calls `_startDownload` from parent
- Show total estimated size (calculate from provider.totalEstimatedDownloadSize)
- Button disabled while preparing/downloading

### Step 6: Integrate into MobileFetchScreen
- Replace `_buildVideoResult` with new `MobileVideoConfigurationWidget`
- Pass callbacks: `onDownload`, `onClear`
- Remove old simple result card
- Ensure state management via VideoProvider

### Step 7: Polish & UX Improvements
- Add loading skeleton (optional)
- Add smooth animations (scale/fade on selection)
- Ensure title doesn't wrap (maxLines: 1, overflow: ellipsis)
- Semi-rounded corners for resolution chips (borderRadius: 20)
- Codec badges with distinct styling
- Responsive spacing for different screen sizes
- Test dark/light theme compatibility

## Files to Modify

1. **NEW**: `lib/ui/widgets/mobile_video_configuration_widget.dart` (main new widget)
2. **MODIFY**: `lib/ui/screens/mobile_fetch_screen.dart` (replace `_buildVideoResult` with new widget)
3. **OPTIONAL**: `lib/providers/video_provider.dart` (if any getter adjustments needed)

## Technical Considerations

- Use existing VideoProvider methods: `selectResolution`, `setSelectedVideoFormat`, `setSelectedAudioMergeStream`, `toggleSubtitle`, `setEmbedSubtitles`
- Total size calculation: provider.totalEstimatedDownloadSize already exists
- Audio only mode: mobile fetch screen already has mode toggle; audio-only will show different UI path
- Subtitles: provider.selectedSubtitles set, embedSubtitles flag
- Themes: Match existing mobile color scheme (purple #8B5CF6 primary)
- Constraints: Mobile screen width ~360-412dp, need vertical scroll

## Success Criteria

- Resolution selector clearly visible below title with non-wrapping title
- Each resolution shows multiple codec variants with clear differentiation
- Audio selection separate and intuitive
- Subtitles easy to select without crowding
- Overall clean, modern, not crammed
- Desktop version unchanged
- Works on various Android screen sizes

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Screen too crowded | Use scrollable sections, compact cards, expansion for subtitles |
| Title wrapping | Enforce maxLines: 1, use smaller font if needed |
| Too many codec variants | List them in scrollable area, show key info only |
| State sync issues | Rely on VideoProvider single source of truth |
| Mobile performance | Use ListView.builder for long lists, avoid nested scrolls |
