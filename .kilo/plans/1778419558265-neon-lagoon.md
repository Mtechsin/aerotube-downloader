# YouTube Downloader (AeroTube) – Missing Features & Improvement Plan

## Overview
This document outlines missing features, bugs, and improvements identified after a thorough codebase review of the AeroTube YouTube Downloader Flutter application (v1.1.0+1).

---

## 1. CRITICAL BUGS & ISSUES

### 1.1. iOS Support Missing
- **File:** `lib/main.dart` (lines 92-96)
- **Issue:** `webViewPath` is only fetched for non-Android platforms (`if (!isAndroid)`), but iOS is never handled. If the app runs on iOS, `webViewPath` will be `null` even when logged in.
- **Impact:** iOS users cannot use WebView-based authentication.

### 1.2. Concurrent Download Queue – Race Condition
- **File:** `lib/providers/download_provider.dart`
- **Issue:** `_processQueue()` is called after every state change (cancel, pause, resume, start, fail), but there is no lock/mutex. Multiple concurrent calls to `_startDownloadInternal` can lead to double-processing.
- **Impact:** Potential duplicate downloads or crashes when multiple downloads finish simultaneously.

### 1.3. `_downloadsBox` Not Closed on Dispose
- **File:** `lib/providers/download_provider.dart`
- **Issue:** Hive boxes (`_downloadsBox`, `_activeDownloadsBox`) are opened but never explicitly closed.
- **Impact:** Resource leak, potential data corruption on app exit.

### 1.4. `_findDownloadedFile` Only Checks Common Extensions
- **File:** `lib/providers/download_provider.dart` (lines 504-525)
- **Issue:** File search uses hardcoded extensions (`.mp4`, `.mkv`, `.webm`, `.m4a`, `.mp3`, `.opus`, `.aac`, `.ogg`, `.wav`, `.flac`) but doesn't cover all possible output formats (e.g., `.flv`, `.3gp`, `.ts` for HLS streams).
- **Impact:** Some downloads may fail to resolve their output file path.

### 1.5. Platform Channel Errors Silently Caught
- **File:** `lib/providers/mobile_download_provider.dart` (lines 137-148)
- **Issue:** `MissingPluginException` and `PlatformException` are silently caught in the `handleError` of the native events subscription, with only a warning logged. No user-facing feedback.
- **Impact:** Users won't know if the native download module fails.

## 2. MISSING FEATURES

### 2.1. No Retry Button for Failed Downloads
- **File:** `lib/ui/widgets/downloads/history_downloads_tab.dart`
- **Issue:** History tab shows failed downloads but there is no "Retry" button for them.
- **Impact:** Users must manually re-enter URL and reconfigure download settings.

### 2.2. No Pause/Resume for Desktop Downloads
- **File:** `lib/ui/widgets/downloads/active_downloads_tab.dart`
- **Issue:** The active downloads tab shows pause/resume controls, but the desktop `DownloadProvider.kill()` simply kills the process. There is no actual pause/resume mechanism (yt-dlp doesn't natively support pause/resume for single files without `--download-archive`).
- **Impact:** Users expect pause/resume to work, but it just cancels and re-queues.

### 2.3. No Video/Audio Quality Picker in Download Config
- **File:** `lib/ui/widgets/video_configuration_widget.dart`
- **Issue:** Users can only select resolution. There's no UI to select audio quality tier (high/mid/low) or specific audio format.
- **Impact:** Users cannot customize audio quality separately from video.

### 2.4. No Batch/Playlist Download from Search
- **File:** `lib/ui/screens/search_screen.dart`
- **Issue:** Search results only allow fetching a single video's info. No option to download all videos from search results or a channel.
- **Impact:** Users must download videos one by one.

### 2.5. No Download Speed Limiter
- **File:** `lib/models/download_item.dart`, `lib/providers/download_provider.dart`
- **Issue:** No option to throttle download speed (e.g., `--limit-rate` in yt-dlp).
- **Impact:** Downloads can saturate bandwidth.

### 2.6. No Filename Template Customization
- **File:** `lib/providers/download_provider.dart` (line 183)
- **Issue:** Output filename template is hardcoded as `'%(title)s.%(ext)s'`. No option for custom output filename templates (`-o` flag customization).
- **Impact:** Users cannot customize how downloaded files are named.

### 2.7. No Multi-URL Batch Download
- **File:** `lib/ui/widgets/url_input_card.dart`
- **Issue:** The URL input only accepts a single URL. No support for pasting multiple URLs (one per line) for batch download.
- **Impact:** Users must download videos one at a time.

### 2.8. No Video Preview/Thumbnail in History
- **File:** `lib/ui/widgets/downloads/history_downloads_tab.dart`
- **Issue:** History items don't show thumbnails or video previews.
- **Impact:** Hard to identify downloads without opening them.

### 2.9. No Audio-Only Download Mode in Mobile UI
- **File:** `lib/ui/screens/mobile_home_layout.dart`, `lib/ui/widgets/mobile_video_configuration_widget.dart`
- **Issue:** The mobile UI does not expose the "Audio Only" toggle that exists in the desktop `VideoConfigurationWidget`.
- **Impact:** Mobile users cannot download audio-only formats.

### 2.10. No Export/Backup of Download History
- **File:** `lib/providers/download_provider.dart`
- **Issue:** Download history is stored in Hive but there's no option to export it (JSON/CSV).
- **Impact:** Users cannot back up or transfer their download history.

### 2.11. No Dark/Light Mode per-Platform Override
- **File:** `lib/ui/screens/settings_screen.dart`
- **Issue:** Theme mode options are "Auto", "Light", "Dark" but there's no per-platform override (e.g., always dark on desktop, always light on mobile).
- **Impact:** Users who want different themes on different devices must change settings manually.

### 2.12. No Custom User-Agent Override
- **File:** `lib/models/app_settings.dart`, `lib/screens/settings_screen.dart`
- **Issue:** No setting to specify a custom User-Agent string for yt-dlp requests.
- **Impact:** Cannot work around site-specific restrictions or use custom bot detection bypass.

## 3. USABILITY & UX IMPROVEMENTS

### 3.1. Empty State Illustrations
- **File:** `lib/ui/screens/home_screen.dart`
- **Issue:** Empty state when no video is loaded uses a basic `AppLogo` widget. No illustration or animation.
- **Improvement:** Add a Lottie animation or custom illustration for empty states (home, downloads, search).

### 3.2. No Toast/Snackbar for Copy Actions
- **File:** `lib/ui/screens/home_screen.dart` (line 768-780)
- **Issue:** When URL is pasted, there's no visual confirmation (toast/snackbar).
- **Improvement:** Show a brief "URL pasted" snackbar.

### 3.3. Missing Haptic Feedback on Mobile
- **File:** `lib/ui/widgets/download_item_card.dart`
- **Issue:** No haptic feedback on tap actions (cancel, pause, delete).
- **Improvement:** Add `HapticFeedback.lightImpact()` on interactive taps.

### 3.4. No Keyboard "Go" Action for URL Input
- **File:** `lib/ui/widgets/url_input_card.dart`
- **Issue:** The keyboard has no "Go" or "Fetch" action button. Users must tap the fetch button manually.
- **Improvement:** Set `textInputAction: TextInputAction.go` on the TextField and handle `onSubmitted`.

### 3.5. No Sorting Options for Downloads
- **File:** `lib/ui/screens/downloads_screen.dart`
- **Issue:** Downloads are displayed in insertion order. No option to sort by date, size, name, or status.
- **Improvement:** Add a sort button in the downloads screen header.

### 3.6. No Filter for Download Status
- **File:** `lib/ui/screens/downloads_screen.dart`
- **Issue:** The "Active" tab shows all active/paused/queued downloads mixed together. No way to show only "downloading" or only "paused".
- **Improvement:** Add a status filter dropdown or chip group.

## 4. PERFORMANCE & MAINTAINABILITY

### 4.1. Unused `download_helper.dart` Import
- **File:** `lib/main.dart`
- **Issue:** `download_helper.dart` is not imported or used anywhere, but `downloadInBackground` from it is used in `ytdlp_service.dart`.
- **Improvement:** Remove unused import if truly unused, or document the dependency.

### 4.2. Duplicate Code: File Discovery Logic
- **Files:** `lib/providers/download_provider.dart` (lines 504-557) and `lib/providers/mobile_download_provider.dart` (lines 740-796)
- **Issue:** File-finding logic is duplicated between desktop and mobile providers with minor differences.
- **Improvement:** Extract into a shared utility `findDownloadedFile()`.

### 4.3. No Pagination in Search Results
- **File:** `lib/ui/screens/search_screen.dart`
- **Issue:** Search results are fetched all at once (default YouTube page size). No "Load more" button.
- **Improvement:** Implement pagination with `--flat-playlist` continuation.

### 4.4. No Memory Limit on Image Cache
- **File:** `lib/main.dart` (lines 70-71)
- **Issue:** `imageCache.maximumSizeBytes` is set to 100MB but not enforced with a count limit.
- **Improvement:** Add `maximumSizeCount` to prevent too many cached images.

### 4.5. `Hive` Box Opening Not Encapsulated
- **File:** `lib/providers/download_provider.dart`
- **Issue:** Hive box names are hardcoded (`'downloads_history'`, `'active_downloads'`).
- **Improvement:** Move to a constants file or use a centralized Hive service.

## 5. SECURITY & RELIABILITY

### 5.1. No HTTPS Certificate Pinning
- **File:** `lib/screens/settings_screen.dart` (update check uses GitHub API)
- **Issue:** No certificate pinning for update checks or API calls.
- **Improvement:** Add certificate pinning for production builds.

### 5.2. Sensitive Data in Logs
- **File:** `lib/services/logging_service.dart`
- **Issue:** Logs may contain URLs which could include sensitive tokens (YouTube cookies in URLs).
- **Improvement:** Sanitize URLs in log output.

### 5.3. No Graceful Shutdown for Active Downloads
- **File:** `lib/providers/download_provider.dart`
- **Issue:** When the app closes, active downloads are terminated abruptly. No grace period.
- **Improvement:** Add a pre-close hook that pauses active downloads before exit.

## 6. TESTING & QUALITY

### 6.1. Minimal Test Coverage
- **File:** `test/widget_test.dart`
- **Issue:** Only a placeholder test exists. No unit tests for providers, services, or utilities.
- **Improvement:** Add tests for:
  - `DownloadProvider.startDownload()`
  - `DownloadProvider.cancelDownload()`
  - `VideoProvider._processFormats()`
  - `YtdlpService.parseProgress()`
  - `PlatformSettingsProvider` initialization

### 6.2. No Integration Tests for Download Flow
- **Issue:** No end-to-end tests for the full download pipeline (URL input → fetch → download → complete).
- **Improvement:** Write integration tests using `integration_test` package.

### 6.3. Missing Error Scenario Tests
- **Issue:** No tests for error handling (network failures, auth failures, disk full, etc.).
- **Improvement:** Add error-path unit tests.
